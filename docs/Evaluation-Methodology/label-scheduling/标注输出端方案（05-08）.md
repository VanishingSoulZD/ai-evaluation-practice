## 05. 自动化质检看门狗（基于 Rubric 规范的自动拦截与一审系统）

- **团队决策：保留（第一道刚性质量防线）**

### 1. 方案详细介绍

自动化质检看门狗是一套嵌入在标注提交后端的**刚性规则过滤引擎**。它通过确定性的代码逻辑、正则表达式、轻量级 NLP 工具及强校验机制，在标注员点击“提交”的毫秒内，对照 Rubric 规范中的底层硬性指标进行高并发扫描。任何不符合最基础交付规范的标注数据（如字数不足、敏感词、JSON 格式错漏、转录文本未加双引号等）都将被该模块直接拦截并秒级弹窗驳回，不允许进入后续昂贵的 LLM 评测或人工二审流。

### 2. 链路位置合规性

处于**标注输出端的第一道关卡**（标注员点击提交 $\rightarrow$ 看门狗自动一审拦截 $\rightarrow$ 通过后流向大模型打分或专家二审）。

### 3. 核心作用与目的

充当高价值算力和专家人力的“防洪堤”。其核心目的是**以接近零算力成本的手段，把 100% 的低级格式错误、无意义灌水文本、不合规常识错误卡在系统之外**，彻底避免后续 `LLM-as-a-Judge` 在垃圾数据上空转 API 费用。

### 4. 方法论有效性根源

数据清洗的“左移原则”（Shift-Left Principle）。质量问题越早在流水线前段被拦截，其修复成本就呈指数级降低。通过机器刚性规则代替人工质检员去肉眼看格式，能够实现零漏判、零情绪波动的绝对标准化质检。

### 5. 链路输入与输出

- **输入（Inputs）：** 标注员在界面提交的原始 Image Caption 文本及表单字段。
- **输出（Outputs）：** \* _通过：_ 标有 `Pass` 标签的数据包，自动放行至下一中枢。
- _拦截：_ 标有 `Reject` 标签，并附带明确触发规则 ID 的错误回执。

### 6. 链路综合提升

将团队整体的质检效率提升数倍。以往质检员需要花费 30% 的精力去揪出“标点符号写错、少填了字段”这类低级错误，现在这部分损耗被压缩至 0。

### 7. 强化学习（RL）涉及度

- **涉及状态：** **不涉及 RL**。本方案属于基于经典软件工程理论的**确定性规则引擎**（Deterministic Rule Engine）。
- **技术平替阐述：** 此处不需要 AI 产生灵感或学习偏好，需要的是 100% 的死板与严苛。底层主要通过 Python 字符串流、Pydantic 模式校验（Schema Validation）以及敏感词 Trie 树匹配来实现。

### 8. 效能衡量与量化方法（对比测试法）

- **核心评估指标：** 漏检率（看门狗放行的数据中，后续仍被 LLM 判定为格式错误的比例，目标为 $0\%$）、拦截吞吐耗时（毫秒级）。
- **量化对比实验设计：** 故意混入 500 条包含“敏感词、漏写标点、字数不达标”的脏数据到提交队列中，观察看门狗的拦截率。若拦截率达到 100% 且全大盘平均响应时间 $\le 50\text{ms}$，则方案达标。

### 9. 落地业务具体示例

- **标注员提交文本：** 一个小男孩穿着短袖站在大楼前面
- **看门狗规则匹配：** \* 规则 01 Check（敏感词）：安全。
- 规则 02 Check（字数限制）：当前 14 字，主观任务要求必须大于 20 字。
- 规则 03 Check（图文文本转录）：检测到图片中大楼有 "SONY" 招牌，但文本中未出现任何双引号包裹的转录词。

- **系统拦截动作：** 界面秒级弹窗提示：“提交失败！1. 您的描述文本不足 20 字，请补充画面细节；2. 检测到背景存在明显商户招牌文字，请严格按照规范进行转录并使用双引号包裹。”

### 10. 落地优先级评分及理由

- **得分：9.5/10**
- **理由：** 研发成本极低（纯代码逻辑），但收效极高。它是任何正规工业化数据工厂不可或缺的“看门狗”，能立刻为团队省下大笔的无效 API 账单。

### 11. 预计落地工期与里程碑

- **总工期：1 周**
- **里程碑：** D1-D2：梳理出首批 15 条刚性拦截 Rubric 规则；D3-D4：基于 Python FastAPI 拦截中间件代码编写与敏感词库加载；D5：上线测试，跑通流程。

### 12. 核心算法与模型选型提示

完全基于 CPU 进行纯工程开发。推荐使用 **Pydantic v2** 进行极速表单反序列化校验，敏感词过滤推荐使用 **FlashText** 算法（其性能在中文字符串匹配上比原生正则快数十倍）。

### 13. 上下游资产依赖条件

依赖方案 06（结构化输出模板）在前端界面将各字段切分清楚。

### 14. 潜在工程风险与规避策略

- **风险：** 规则过胖或误伤。如果把模糊的语义规则（如“描写得不够优美”）也写成刚性代码，会导致标注员被无限卡死，产生极大的挫败感和对抗情绪。
- **规避策略：** 看门狗**只管客观格式，不管主观语义**。语义层面的好坏一律放行，交给后端的大模型裁判去裁决。

## 06. 结构化标注输出模板（基于 Schema 约束的分维度表单基建）

- **团队决策：保留（全平台数据流的数字化地基）**

### 1. 方案详细介绍

本方案彻底废除过去传统数据平台上“一个大文本框让标注员自由发挥”的落后作业形态。通过在前端界面推行**基于 JSON Schema 强约束的分维度结构化表单**，强制要求标注员必须按照“核心主体、空间位置、背景环境、文字渲染、美学风格”等 5 大多维核心矩阵，拆碎了填表。同时，表单内置了级联逻辑与元素绑定机制，使每一条标注产物在诞生之初就是高度结构化的。

### 2. 链路位置合规性

处于**标注作业界面层**（标注员正在生产数据的生产工具本身）。

### 3. 核心作用与目的

规范人的思维路径，消除语义模糊。确保标注产物能够无缝适配后端的 `LLM-as-a-Judge` 评测框架。只有输入端是高度结构化的对象，后端的自动化路由、算账、返工系统才能进行精准的字段级对齐与因果推导。

### 4. 方法论有效性根源

从软件工程角度看，“Garbage in, garbage out（垃圾进，垃圾出）”。自由文本隐含了巨大的歧义性，而结构化表单将复杂的自然语言图像描述（Image Caption）转译为了**机器可解析的特征矩阵**。这降低了数据噪声，显著提升了后续训练微调自研 T2I 模型时的文本条件对齐度。

### 5. 链路输入与输出

- **输入（Inputs）：** 标注员面对的原始待标图片与提示意图。
- **输出（Outputs）：** 标准的、分字段的结构化 JSON 数据对象。

### 6. 链路综合提升

实现数据资产的“即查即用”。算法人员可以一键筛选出所有“背景为夜景且包含两个主体”的完美结构化切片数据，无需再用正则表达式去大海捞针。

### 7. 强化学习（RL）涉及度

- **涉及状态：** **不涉及 RL**。本方案属于纯粹的**前端工程与交互设计基建**。
- **技术平替阐述：** 其核心是利用 Ant Design / Vue Element 等前端组件库，配合标准的 JSON Schema 校验协议锁死输入边界。

### 8. 效能衡量与量化方法（对比测试法）

- **核心评估指标：** 数据结构化率（100%）、标注员首件数据录入耗时（用于评估表单是否过于繁琐）、后续算法直接解析成功率（100%）。
- **量化对比实验设计：** 观察上线前后，后端大模型进行 Rubric 解析时的报错率。上线前因标注员漏写维度导致的解析失败率如果为 15%，上线后应降为 0%。

### 9. 落地业务具体示例

平台的后端最终收到的不再是一段话，而是一个纯净的 JSON 报文：

```json
{
  "task_id": "t2i_9921",
  "main_subject": {
    "count": 1,
    "description": "一名年轻的宇航员",
    "actions": "双手抱胸，面带微笑"
  },
  "spatial_layout": [
    { "subject": "宇航员", "position": "画面正中央" },
    { "subject": "地球", "position": "左上角背景，部分遮挡" }
  ],
  "text_rendering": {
    "has_text": true,
    "text_content": "NASA",
    "position": "宇航员头盔右侧反光处"
  }
}
```

### 10. 落地优先级评分及理由

- **得分：9/10**
- **理由：** 它是整个白皮书体系得以运转的**数据普通话**。如果这一步不做，后续的所有“自动打分、自动返工、智能调度”都会因为无法精准解析文本而沦为空中楼阁。

### 11. 预计落地工期与里程碑

- **总工期：2 周**
- **里程碑：** W1：联合算法团队、质检团队闭门对齐文生图多维度 JSON Schema 规范；W2：前端动态表单渲染组件开发与级联校验逻辑联调。

### 12. 核心算法与模型选型提示

纯前端与后端表单架构开发。核心提示：表单设计必须遵循“轻量化”原则，善用下拉选择框（Select）和勾选框（Checkbox）替代部分自由文本框，最大限度降低标注员的键盘敲击次数。

### 13. 上下游资产依赖条件

下游方案 07（返工修复器）严重依赖本方案提供的字段级定位能力。

### 14. 潜在工程风险与规避策略

- **风险：** 表单过于冗长死板，导致标注员产生严重的排斥心理，单条数据标注耗时飙升，引发“效率断崖式下跌”。
- **规避策略：** 引入“动态自适应表单”。如果标注员勾选了“画面中无文字”，则“文字内容、文字字体、文字颜色”等后续 5 个子表单字段自动在界面隐藏，绝不让标注员填写任何无意义的空白字段。

## 07. 返工修复器（基于 LLM Judge 评语的精准指导返工助手）

- **团队决策：保留（重点攻克的高 ROI 提效神器，强烈推荐 🌟）**

### 1. 方案详细介绍

返工修复器是本架构中**最具人情味且回报率极高的工程解法**。当后端的评测裁判（方案 09）判定某条标注数据不及格并触发返工逻辑时，本模块会把大模型产生的那些晦涩、冗长、纯学术风的原始 Raw JSON 报错日志和扣分评语抓取过来。通过一个专职的“人话适配层”，将这些冷冰冰的裁判评语转化为“保姆级的、直接在前端界面高亮红线框定的修改向导”。它直接告诉标注员：“你的第 3 字段写错了，漏掉了背景里的那匹马，请在这里补上”，彻底实现定向修复。

### 2. 链路位置合规性

处于**标注输出端的返工流循环中**（大模型判定不及格 $\rightarrow$ 返工修复器生成保姆向导 $\rightarrow$ 标注员在被高亮的专用界面进行精准二次修改）。

### 3. 核心作用与目的

**打破低效返工的死循环。** 传统模式下，标注员被退单后只能看到一个总分（如“60分，不及格”）或一句笼统的“信息不全”，只能像无头苍蝇一样盲目重写，导致一条数据反复折腾 4-5 遍。本方案旨在实现“看图抓药，一次改对”，单条样本的返工次数预期直接斩断至 1 次以内。

### 4. 方法论有效性根源

认知心理学中的“即时定向反馈机制”。人类在面对具体的、具象化的、带有锚定点的错误提示时，大脑的修正行为耗时最短、准确度最高。通过将 LLM 强大的语意洞察力转化为直观的 UI 视觉交互，完美消除了“大模型裁判的超高标准”与“普通标注员执行力”之间的鸿沟。

### 5. 链路输入与输出

- **输入（Inputs）：** 方案 09（`LLM-as-a-Judge`）吐出的多分枝详细扣分 JSON 报文、标注员最初提交的带有字段 ID 的数据包。
- **输出（Outputs）：** 前端工作台界面上呈现的“红线高亮输入框 + 气泡流诊断评语 + 一键定位向导”。

### 6. 链路综合提升

将团队的“返工周期”整体压缩 70% 以上，显著提升标注员的心态健康度与留存率（不再因无效盲目重写而焦虑怨恨系统），同时直接拉高最终交付资产的综合纯净度。

### 7. 强化学习（RL）涉及度

- **涉及状态：** 本方案本身为确定性 UI 渲染层，**不直接涉及在线 RL**。但它输出的精确返工产物，是后续方案 01 和方案 14 强化学习网络中最重要的“正负样本演练场”。

### 8. 效能衡量与量化方法（对比测试法）

- **核心评估指标：** **二次交付通过率（Rework Success Rate at First Attempt）**、返工修改耗时、人均单日吞吐量。
- **量化对比实验设计：** 收集 1000 条被大模型裁判打回的错漏样本。
- 传统盲改组（500条）：仅提示“图文空间不匹配，请重新修改”，让标注员自行发挥。
- 智能向导组（500条）：使用本方案，在界面高亮报错字段并贴出保姆级气泡评语。
- 严格统计两组的“一改通过率”**（一次修改即成功放行的比例）和**平均返工耗时（分钟/条）。

### 11. 预计落地工期与里程碑

### 12. 核心算法与模型选型提示

在后端解析原始 JSON 报错后，如果发现报错文本过于晦涩，可调用一个非常轻量、便宜的文本大模型（如 Qwen2.5-3B-Instruct 或公司内部的 nano 模型）配上几组 Few-shot 示例，花万分之一美分的成本将其快速洗成“人话版气泡评语”，随后通过 WebSocket 实时推送到前端渲染。

### 14. 潜在工程风险与规避策略

- **风险：** 评语翻译出现二次误导。如果轻量大模型在把裁判语洗成“人话”时理解错了意思，瞎指挥标注员修改，会导致标注员更加愤怒。
- **规避策略：** 在前端气泡框底部保留一个“查看原始裁判日志”的微型折叠按钮，允许高级标注员在对人话提示产生怀疑时，一键展开看最原始的英文/学术风报错归因。

## 08. 标注员行为建模与个体校准（基于一致性概率的画像管理）

- **团队决策：战略移除 / 暂缓（ROI 极低，不符合现阶段国情）**

### 1. 方案详细介绍

本方案试图通过在后台部署一套贝叶斯概率网络或项目反应理论（Item Response Theory, IRT）模型，对每个注册标注员的每一次历史提交进行全量行为建模。通过统计他们面对不同难度图片时的打分偏置、漏标概率、耗时分布，为每个人画出一幅精准的“主观主观方差画像”，并在最终数据聚合时，利用该画像的统计权重对每个人的标注数据进行反向数学概率校准。

### 2. 链路位置合规性

处于**复核端与后端数据终验产出层之间**。

### 3. 核心作用与目的

通过数学手段消除不同标注员之间的主观审美和严苛度方差。例如：把“天生手松”的标注员的分数往下乘一个系数，把“天生严苛”的标注员的分数往上提一个系数，从而在统计学上拉平大盘标准。

### 4. 方法论有效性根源

底层基于众包统计学中的群体对齐演算法。通过计算标注员与群体均值或专家黄金标准（Gold Standard）之间的 Fleiss' Kappa 一致性概率，剔除行为异常的标注个体。

### 5. 链路输入与输出

- **输入（Inputs）：** 标注员历史一万条数据的打分记录、耗时序列、质检被打回的历史概率。
- **输出（Outputs）：** 动态更新的《标注员特征画像高维权重矩阵》。

### 6. 链路综合提升

理论上能在不增加人工二审比例的前提下，通过后台纯数学计算提升海量众包数据的整体一致性。

### 7. 强化学习（RL）涉及度

- **涉及状态：** **不涉及 RL**。属于经典的**统计机器学习与概率图模型**。

### 8. 效能衡量与量化方法（对比测试法）

- **核心评估指标：** 校准后的大盘全局标准差减低幅度、模型收敛平滑度。

### 9. 落地业务具体示例

### 10. 落地优先级评分及理由

- **得分：2/10**
- **理由：战略移除/暂缓。** 该方案属于典型的“算法团队自嗨型高智商低 ROI 陷阱”。在实际的文生图工厂业务中，底层标注员的离职率和流动性极高（往往两周就换一批新人），机器学习模型根本没有足够的历史冷启动数据去对一个高流动性的个体建立稳定的统计画像。维护这套画像模型的算法人力成本，远不如推行方案 05（看门狗）和方案 06（强格式模板）来得简单粗暴且见效快。
