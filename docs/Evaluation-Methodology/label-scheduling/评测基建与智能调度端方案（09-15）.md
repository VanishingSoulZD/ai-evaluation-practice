## 09. 多模态被动打分器（基于自建 LLM-as-a-Judge 的定制 Rubric 打分中枢）

- **团队决策：保留（作为平台已落地的核心资产，进行压缩介绍）**

### 1. 方案详细介绍

作为团队**已落地运营的底层资产**，本方案通过调用公司提供的多模态大模型 API 矩阵，让 AI 扮演严苛的多模态裁判。系统输入图文对后，大模型依据线上动态加载的 Rubric（质检量表）标准文本，逐项输出文本归因理由，并返回结构化的分维度得分。

### 2. 链路位置合规性

处于**评测基建层的第一核心轨道**（承接标注输出端的产物，为后续的智能调度大脑提供全量特征报文）。

### 3. 核心作用与目的

充当全平台的“多维诊断眼”。其核心价值不在于单纯的标量打分，而在于其**极高的可解释性**，能够通过文本评语为方案 07（返工修复器）提供字段级的报错逻辑来源。

### 4. 方法论有效性根源

基于强对齐大模型在少样本（Few-Shot）和复杂语义推理上的涌现能力。通过将人类的《标注指南》转化为大模型的上下文 Rubric Prompt，能够模仿高级质检专家的逻辑链条，对图像进行像素级与语意级的深度审视。

### 5. 链路输入与输出

- **输入（Inputs）：** 方案 06 提交的结构化标注 JSON（Prompt、Caption）、下游生成的 T2I 图像、当前任务的 Rubric 提示词模板。
- **输出（Outputs）：** 包含多分枝扣分原因、视觉冲突证据、特定字段 ID 的强类型 JSON 诊断报文。

### 6. 链路综合提升

替代了 80% 的日常人工一审复核工作，将每条数据的多维度精细化审视成本从数元人民币压缩至数分钱。

### 7. 强化学习（RL）涉及度

- **涉及状态：** 本方案作为既有资产，在线运行时**不涉及在线 RL**，属于被动的生成式推理。

### 8. 效能衡量与量化方法

- **核心评估指标：** AI 裁判与人类专家组长打分的一致性系数（Cohen's Kappa $\ge$ 0.72）、高频扣分项的业务召回率。

### 9. 落地业务具体示例

- **业务状态：** _已全面上线稳定运行_。在前线业务中，它正通过模型，将一条“手部画崩、手指残缺”的图片精准判定为 `{"dimension": "aesthetic_details", "score": 40, "reason": "手部区域出现明显生理结构畸变，左手无名指与小拇指发生粘连融化"}`。

### 10. 落地优先级评分及理由

- **得分：10/10（已落地资产，生命线级基建）**

### 11. 预计落地工期与里程碑

- **当前状态：** 已于上个周期交付，目前处于日常维护与 Prompt 提示词微调阶段。

### 12. 核心算法与模型选型提示

动态路由调用：日常任务使用“nano banana”以节省 Token 成本；高价值旗舰 T2I 模型评测则强行绑定自研大模型。

### 13. 上下游资产依赖条件

依赖方案 06 提供的多维度切片字段，为方案 07 提供保姆级返工气泡数据源。

### 14. 潜在工程风险与规避策略

- **风险：** 大模型裁判的“大模型幻觉”或判罚标准随 API 版本更新而产生不可控的漂移。
- **规避策略：** 锁死 API 的 `temperature=0`，并由方案 11（逆向校准系统）进行每日自动化抽检监控。

## 10. 基准奖励模型评估器（基于 ImageReward/PickScore 的经典判别式 RM 引入）

- **团队决策：保留（作为并列双轨制的新增硬核基建，深度展开）**

### 1. 方案详细介绍

为了弥补方案 09（LLM-as-a-Judge）在速度、算力成本及宏观偏好定量化上的天然缺陷，本方案正式引入**经典的判别式奖励模型（Reward Model）作为评测的第二轨道**。本方案不依赖昂贵的大模型生成文字评语，而是直接在本地私有化部署基于 ImageReward 或 PickScore 架构的轻量级视觉-文本双塔偏好网络。它直接通过数学点积计算，毫秒级输出一个绝对的标量分（Scalar Score），用以高精度表征该图文对符合人类宏观普遍审美品味的概率概率。

### 2. 链路位置合规性

与方案 09 并列，处于**评测基建层的第二核心轨道**。它是微观调度、价值算账（方案13）以及下游 DPO 训练直接调用的高并发打分中枢。

### 3. 核心作用与目的

打造平台的“宏观测速仪”与“低成本过滤器”。在海量生图吞吐或宏观算法路由（方案14）时，提供零 Token 成本、极速的宏观质量打分，并直接为下游自研模型的 DPO（直接偏好优化）提供纯净的偏好数据对。

---

### 🔀 【架构深度对齐】生成式双轨裁判 vs 判别式双轨裁判

为了让团队清晰理解双轨制的工程分工，以下将两者的底层差异和输入输出映射进行全景对比：

| 维度         | 方案 09：生成式裁判（LLM-as-a-Judge）              | 方案 10：判别式裁判（经典 Reward Model）        |
| ------------ | -------------------------------------------------- | ----------------------------------------------- |
| **底层原理** | 自回归大模型根据 Rubric 文本**生成**解释与分数     | 双塔/融合网络直接**预测**人类偏好的标量概率值   |
| **核心优势** | **可解释性极强**，能说清楚错在哪里（有理有据）     | **速度极快、成本极低**，天然契合人类微妙审美    |
| **核心劣势** | 耗时久（秒级）、Token 费用高、难以定量微小差异     | 黑色箱子（Black Box），无法提供任何文本修改意见 |
| **系统分工** | **负责“精细质检”与“指导返工”**（针对不及格的个体） | **负责“宏观筛单”与“高速算账”**（针对海量大盘）  |

#### 📥 双轨制输入与输出流图解

```
                   ┌──> [ 方案 09: LLM-as-a-Judge ] ──> 输出: 复杂的 JSON 诊断报文 (用以返工)
                   │
[ 标注图文对数据 ] ─┤
                   │
                   └──> [ 方案 10: 经典 Reward Model ] ──> 输出: 标量浮点数 R(x,y) (用以调度算账)

```

---

### 4. 方法论有效性根源

判别式奖励模型通过在大规模人类真实偏好选择数据集（如 $A > B$ 的 Side-by-Side 投票数据）上进行对比损失函数（Contrastive Loss）训练。模型通过学习将视觉 Embedding 与文本 Embedding 映射到同一个高维人类偏好空间，其输出的标量分在宏观统计学上与人类的真实喜好具有极高的相关性（Human Alignment）。

### 5. 链路输入与输出

- **输入（Inputs）：** 提示词文本 $x$（Prompt）、生成的对应图片 $y$。
- **输出（Outputs）：** 一个纯粹的标量浮点数 $R(x, y)$（例如：`0.8752`），分值越高代表图文对齐度与画面美学度越契合人类普遍偏好。

### 6. 链路综合提升

实现“毫秒级质量宏观过滤”。在面对每周大批量（如数万条）的微调模型效果大炼兵时，无需空转昂贵的生成式 API，直接用本地 GPU 阵列在几分钟内跑完大盘总分，算力 ROI 提升数百倍。

### 7. 强化学习（RL）涉及度

- **涉及状态：** **深度涉及 RL 基建**。本方案本身就是强化学习技术栈中的 **Reward Function（奖励函数）** 实体。
- **【小白/PM 降维释义层 —— 角色扮演】：**
  > - **Policy（策略 / 也就是下游正在训练的自研生图大模型）：** 它像是一个努力学画画的学生。
  > - **State（状态）：** 老师给出的画题：“画一只金色的独角兽”。
  > - **Action（动作）：** 学生（生图大模型）挥毫泼墨，画出了一张图片。
  > - **Reward（奖励 / 本方案扮演的经典 RM 裁判）：** 这张图不需要送去让人类看，也不需要送去给昂贵的大大模型写评语。本方案的经典 RM 像一个内置的“金牌考官机器”，眨眼之间就看完了图，直接在后台给出一个分数：**“+3.5分”** 或者 **“-2.0分”**。生图大模型（Policy）在 DPO 或 PPO 训练中，就是为了让这个考官多给正分，从而知道哪些笔触是人类喜欢的，哪些是讨厌的。

### 8. 效能衡量与量化方法（对比测试法）

- **核心评估指标：** **偏好预测准确率（Preference Accuracy）**。
- **量化对比实验设计：** 抽取 2000 对人工已经完成 Side-by-Side 盲测投票（即确定 A 图优于 B 图）的真实历史文生图对。将这 2000 对样本输入本方案的模型中，统计模型输出的分数是否满足 $R(\text{Image A}) > R(\text{Image B})$。计算其判定一致率：

$$\text{Accuracy} = \frac{\sum \mathbb{I}(R(A) > R(B))}{2000}$$

指标达到 $75\%$ 以上即视为高分可用。

### 9. 落地业务具体示例

- **系统调用流：** 下游模型微调生成了 5000 张图。调度系统直接调用本地部署的 `PickScore-ViT-H` 推理集群。
- **秒级响应：** 耗时 4.2 秒，5000 张图全部被打上标量分。系统一键过滤出分数处于后 10% 的 500 张“低美学度/严重穿模”的废片，直接打包送入方案 13 进行价值重估，完全不需要惊动高昂的生成式大模型裁判。

### 10. 落地优先级评分及理由

- **得分：9.5/10**
- **理由：** 它是数据标注团队迈向高级“强化学习数据工厂”的必经之路。有了这个标量打分器，我们才能在后续的方案 13 和 14 中进行真正的“数学算账”与“动态路由”，实现真正的智能化调度。

### 11. 预计落地工期与里程碑

- **总工期：3 周**
- **里程碑：** W1：在本地英伟达算力环境上部署 ImageReward 和 PickScore 开源基线模型；W2：使用团队内部积累的 5 万条历史人工 Side-by-Side 偏好数据对模型进行微调（LoRA Alignment）；W3：将打分接口封装为高并发 RPC 服务，并入双轨制评测流。

### 12. 核心算法与模型选型提示

推荐选用 **PickScore (基于 CLIP-ViT-H-14 骨干网络)**。在工程实践中，PickScore 对视觉构图和微观人类审美的捕捉敏感度显著优于传统的 BLIP 架构，且模型极其轻量，单张消费级显卡即可实现极高的吞吐。

### 13. 上下游资产依赖条件

依赖方案 06 导出的纯净图文对资产，作为其推理输入。

### 14. 潜在工程风险与规避策略

- **风险：** 判别式 RM 存在“视网膜盲区”（例如它对图片整体美学很敏感，但对文本中的细粒度数量词如“三个苹果”完全没有数数能力）。
- **规避策略：** **绝不单独使用标量分作为唯一放行标准**。必须与方案 09 的结构化 Rubric 进行加权融合，或者通过规则引擎强制卡死数量、空间等核心硬性指标。

## 11. 评测器自身逆向校准系统（基于人类专家覆判反馈的 HITL 优化）

- **团队决策：保留（防范 AI 裁判权力滥用的安全绳）**

### 1. 方案详细介绍

本方案是一套针对方案 09（LLM-as-a-Judge）和方案 10（经典 RM）的**人类反馈在环校准系统（Human-in-the-loop, HITL）**。当标注员对双轨制裁判给出的扣分 verdict 感到不服，或者自动化看门狗（方案05）检测到 AI 裁判的分数出现异常时，可以在工作台一键发起“不服仲裁”。该样本会瞬间被路由至高级专家组长肉眼复核。专家做出的终审判决不仅会覆盖 AI 裁判的结果，还会自动转化为一条“校准对齐真值数据”，反向微调或纠偏 AI 裁判的 Prompt 触发边界。

### 2. 链路位置合规性

处于**评测中枢的后台自愈更新流水线**。它作为旁路监控器，横跨评测端与专家复核端。

### 3. 核心作用与目的

**对抗“AI 裁决漂移”与“机器偏见”。** 保证系统规则的长效正义性，平息标注团队前线人员对机器判罚不公的对抗情绪，确保 AI 裁判的判罚尺度永远与公司最高级专家的审美眼光处于绝对共振状态。

### 4. 方法论有效性根源

基于监督微调中的难例对齐（Hard Negative Alignment）。AI 模型的错例往往暴露出其隐空间在特定提示词边界上的模糊性。通过捕捉这些“机器判错、人类判对”的高价值争议样本（Controversial Examples），进行定向的 Few-shot 增补或参数微调，能以极小的数据量产生最高的泛化对齐收益。

### 5. 链路输入与输出

- **输入（Inputs）：** 标注员发起的仲裁申诉请求、AI 裁判原始 JSON 报错日志、高级专家终审给出的标准化订正 Schema。
- **输出（Outputs）：** 定向订正后的打分结果、自动归档至《AI裁判错题库》、触发方案 09 的 Prompt 增量升级指令。

### 6. 链路综合提升

彻底告别“AI 裁判一旦判定出错，只能由后端开发手工去改代码 Prompt，按下葫芦浮起瓢”的作坊式打补丁形态，实现评测体系的线上自我进化。

### 7. 强化学习（RL）涉及度

- **涉及状态：** **深度涉及 RL 中的人类反馈（Human Feedback）对齐流**。
- **【小白/PM 降维释义层 —— 角色扮演】：**
  > - **我们的 AI 裁判（方案 09/10）：** 刚上岗时，它虽然聪明，但偶尔会犯糊涂（比如把一幅具有“朦胧国画美”的艺术图误判为“高糊穿模废片”）。
  > - **人类高级专家（HITL 仲裁官）：** 当标注员委屈地大喊“裁判吹黑哨”并提起申诉时，这位仲裁官就会接入，看一眼图说：“这叫艺术，不是穿模！AI 判错了，改判！”
  > - **逆向校准干预：** 系统不仅把分数改过来，还会把这次改判的“全案卷宗”记录下来，像训小狗一样敲打一下 AI 裁判：“看好了，以后这种国画风格的朦胧感不准再扣分了！”AI 裁判在后台更新了自己的记忆，以后就会越来越像这位人类专家的行笛风格。

### 8. 效能衡量与量化方法（对比测试法）

- **核心评估指标：** **申诉改判率（Appeal Overturn Rate）**（改判率应随系统运行周环比持续收敛）、AI 裁判错例自动迭代收敛耗时。
- **量化对比实验设计：** 故意挑选 200 条处于判罚模糊地带的国风/二次元复杂美学样本。A 组直接沿用老版 AI 裁判进行判罚；B 组在经历了一周的人类专家 HITL 逆向校准后，由新版 AI 裁判进行判罚。对比两组判罚结果与专家最终人工盲测答案的重合度，重合度提升 $\ge 12\%$ 视为校准系统显著有效。

### 9. 落地业务具体示例

- **标注员动作：** 标注员小张提交了一幅“水墨风格”的文生图描述，LLM Judge 触发了方案 09，因“画面边缘线条不锐利、有大面积墨迹晕染”判定为次品扣 30 分。
- **系统流转：** 小张在界面点击 `[不服，申请专家覆判]`。该单自动弹窗到质检组长电脑上。组长勾选 `[属于特定艺术风格，并非穿模缺陷]`，一键纠正为放行。
- **反向对齐：** 系统自动提取该样本，并在方案 09 的 Rubric 负面提示词定义中自动增补一行 Few-shot：`"Note: High-end artistic ink-wash blur effects should NOT be categorized as 'blurry artifacts'."`。次日，同类水墨风样本的错判率瞬间归零。

### 10. 落地优先级评分及理由

- **得分：8/10**
- **理由：** 它是整个自动化大厦的“保险丝”。没有逆向校准系统，人工团队就会对自动化评测平台产生极大的信任危机。把它立起来，能够确保标注体系在拥抱 AI 的同时，牢牢掌握人类专家的终极控制权。

### 11. 预计落地工期与里程碑

- **总工期：2 周**
- **里程碑：** W1：在标注工作台和质检工作台开发“一键申诉”与“专家仲裁看板”前端 UI；W2：开发后台错题本自动聚类与 Prompt 动态热插拔拼接引擎，正式上线。

### 12. 核心算法与模型选型提示

前端 UI 交互与数据库状态流开发。对于方案 10（经典 RM）的反向校准，系统会把积累满 1000 条的仲裁对齐数据自动打包，在每周日凌晨自动触发一次 PickScore 底层全连接层的增量梯度反向传播（Incremental Fine-tuning）。

### 13. 上下游资产依赖条件

依赖方案 09、10 必须暴露出可动态插拔更改的配置接口。

### 14. 潜在工程风险与规避策略

- **风险：** 标注员滥用申诉权利。如果没有任何门槛，标注员为了洗白自己的低质数据会疯狂点击申诉，导致高级质检组长被淹没在仲裁泥潭中。
- **规避策略：** 引入“恶意申诉扣减积分惩罚机制”。如果专家组长判定申诉完全无理（纯属标注员胡搅蛮缠），则倒扣该标注员的日结通过率积分；若申诉成功则奖励积分。通过这个微观激励杠杆，强制标注员只对真正的“机器误判”发起高质量申诉。

## 12. 宏观需求分发器（基于 Failure Slicer 的历史扣分点弱项聚类分析）

- **团队决策：保留（宏观任务派发的指南针）**

### 1. 方案详细介绍

本方案是一个宏观层面的数据诊断与需求挖掘引擎。它在每个评测周期（如每周）结束时启动，自动抓取大盘数万条样本的结构化 Rubric 扣分数据（方案 09）。通过特征提取与无监督聚类算法（Failure Slicer），将模型在不同 prompt 场景下的泛化失败点进行多维切片，找出自研文生图模型当前的“系统性硬伤”，并自动将这些硬伤转化为下周标注团队的《定向数据采购与派单需求书》。

### 2. 链路位置合规性

处于**评测周期结束后的分析汇总层**，反向作用于下一周期的**标注输入端（方案 03 采样器）**。

### 3. 核心作用与目的

告别“盲人摸象”式的需求沟通。解决算法团队和数据团队之间“模型到底哪里弱、下周该标什么”的长期扯皮，通过全量数据挖掘，直接指明大模型当前的研发短板。

### 4. 方法论有效性根源

利用了无监督聚类中的“主成分错误归因”。大模型生成的错误图片虽然千奇百怪，但在多维 Rubric 向量空间中，相同逻辑缺陷（如“左边、右边等方位词高频对齐失败”）的投影会高度聚集。通过捕捉这些错误高发区（Error Hotspots），能够以最快速度定位模型由于预训练数据不足带来的“认知盲区”。

### 5. 链路输入与输出

- **输入（Inputs）：** 上一周大盘跑出的 100,000 条结构化 Rubric 报错报文（包含扣分分值、文本理由嵌入向量）。
- **输出（Outputs）：** 聚类后的《模型三大系统性缺陷白皮书》及直接可导入派单系统的需求权重 JSON。

### 6. 链路综合提升

- **技术平替阐述：** 它不需要在线试错，它像一个“错题统计专家”，把过去一周全班学生的错题本堆在一起，按照错误原因分类，最后在黑板上写出：“本周全班在‘空间方位几何几何题’上错得最多，下周重点补习这一块”。

## 13. 样本价值评估器（基于 Utility Model 的重标/复审增量收益预测）

- **团队决策：保留（整个大脑的“精算师”，架构基石 🌟）**

### 1. 方案详细介绍

智能调度的核心在于“算账”。本方案构建了一个**基于边际效用理论（Utility Theory）的价值预测模型**。当一条标注数据在评测端产生结果后，本模块负责计算“若对该样本追加资源（如：让原人返工、或者多花 5 块钱送给高级专家二审仲裁），它能给下游 T2I 模型带来多大的边际提分收益”。模型通过综合评估该样本的难易度、当前模型的缺陷紧迫度以及标注员的执行上限，为每条动作计算出一个绝对的“期望效用值（Expected Utility）”，从而量化数据运作的 ROI。

### 2. 链路位置合规性

处于**评测结果输出后、微观路由动作发生前**。它是微观路由器的前置精密计算芯片。

### 3. 核心作用与目的

**量化每一条数据的经济价值。** 彻底根治“所有不及格样本一律退回人工重标”或“遇到争议一律请专家”的土豪式浪费行为，把钱花在刀刃上。

### 4. 方法论有效性根源

基于运筹学中的边际收益递减与风险决策理论。一条原本就能拿 85 分的优秀样本，再花钱请专家精修到 95 分，对 T2I 模型能力的提升微乎其微（Utility 接近 0）；而一条处于模型弱项核心区、当前得分为 40 分的潜力样本，一旦通过专家拨乱反正修到 90 分，将释放巨大的梯度回传价值。本方案通过数学公式对这种“改命价值”进行了精准度量。

### 5. 链路输入与输出

- **输入（Inputs）：** 当前样本 $s$ 的分维 Rubric 得分向量、当前自研 T2I 模型的宏观缺陷权重向量。
- **输出（Outputs）：** 该样本在各种潜在调度动作下的效用值矩阵 $U(s, a)$。

---

### 🔏 【核心精算数学公式构建】

为了确保调度的严谨性，系统对单条样本 $s$ 采取特定调度动作 $a$（如：$a_1=\text{Pass}, a_2=\text{Rework}, a_3=\text{Expert}$）时的边际效用 $U(s, a)$ 建模如下：

$$U(s, a) = \frac{\mathbb{E}[\Delta R(s) \mid a] \times w_{\text{macro}} - C(a)}{C(a)}$$

其中：

- **$\mathbb{E}[\Delta R(s) \mid a]$**：基于历史数据回归预测的、在动作 $a$ 下该样本经典奖励模型（方案 10）分数的**期望提升幅度**。
- **$w_{\text{macro}}$**：由方案 12（宏观分发器）实时动态更新的**模型弱项紧迫度权重系数**（若该样本特征属于模型当前急需的死角，该值从 $1.0$ 飙升至 $2.5$）。
- **$C(a)$**：执行动作 $a$ 的**刚性成本开销**（以法币或算力 Token 计价，如 $C(\text{Rework})=0.2$ 元，$C(\text{Expert})=5.0$ 元）。

---

### 6. 链路综合提升

实现数据资源的“精细化套利”。通过卡死 $\text{ROI} > \text{Threshold}$ 的硬性门槛，平台能够自动放弃那些“重标成本极高但对模型毫无帮助”的顽固难例，专攻“低投入、高回报”的黄金高收益样本。

### 7. 强化学习（RL）涉及度

**涉及状态：** **间接涉及 / 为在线 RL 决策提供核心价值对齐（Value Alignment）的底层函数。**
**技术平替阐述：** 本方案计算的边际效用 $U(s, a)$ 并非由强化学习智能体通过在线试错（Trial and Error）学出，而是通过离线监督回归树模型对历史数据进行提分期望预测。然而，它产出的边际效用矩阵，直接作为方案 14（Bandit 路由器）这一标准在线强化学习算法的**关键上下文特征输入（Context）与动作空间收益期望（Expected Reward）**。它利用运筹学精算公式，将高维的多模态质量拉升转化为一维的经济学效用，是整个强化学习调度大脑不可或缺的“价值度量衡”。

### 8. 效能衡量与量化方法（对比测试法）

- **核心评估指标：** 预算节省率、每万元标注成本换来的 T2I 模型 Benchmark 提分效率。
- **量化对比实验设计：** 准备 10,000 条处于不及格边缘（50-65分）的真实生图标注数据，申请 2 万元预算。
- 传统组：不引入价值评估，按照老规矩“只要不及格，一律平均分配预算送专家二审”，直到预算耗尽。
- 本方案精算组：由评估器为每条样本算账，优先挑出期望效用 $U$ 最高的样本执行专家二审，其余的降级为原人返工或直接放行。
- 最终用两组洗出来的优质数据微调同一个基座模型，对比 Benchmark 得分。精算组预计能用 **$40\%$ 的预算消耗，达成与传统组 100% 预算对等的模型性能增量**。

### 9. 落地业务具体示例

- **线上状态：** 样本 $s$ 是一张“中国古代亭台楼阁”的生图标注，当前多模态裁判（方案09）打分为 55 分（空间关系杂乱）。
- **算账结果：** 评估器调取参数计算：由于“古建筑空间”是下周模型微调的 A 级核心弱项（$w_{\text{macro}}=2.2$），且回归历史曲线发现，这类图片一旦由高级专家（Cost = 5元）重标 Caption 引导，生图模型的 ImageReward 分数（方案10）平均能暴涨 0.45 分（$\mathbb{E}[\Delta R] = 0.45$）。
- **效用输出：** 计算得出 $U(s, \text{Expert}) = \frac{0.45 \times 2.2 - 5.0}{5.0} = -0.80$（专家太贵，划不来）。而系统同时算出了另一个动作：原人带气泡指南返工（Cost = 0.5元，期望提分 0.3 分），$U(s, \text{Rework}) = \frac{0.3 \times 2.2 - 0.5}{0.5} = +0.32$。
- **决策指示：** 打印账单：**“原人返工”效用值为正，专家效用值为负。建议走原人返工流程。**

### 10. 落地优先级评分及理由

- **得分：9.5/10**
- **理由：** 这是整个智能调度大厦的“数学底座”。没有这套 ROI 算账公式，后续的任何算法调度都会失去目标函数。

### 11. 预计落地工期与里程碑

- **总工期：4 周**
- **里程碑：** W1-W2：收集历史各工种（原人、组长、专家）改单后的提分统计数据，拟合回归效用曲线；W3：在后端用 Go/Python 实现单条样本的效用矩阵实时计算引擎；W4：全线联调。

### 12. 核心算法与模型选型提示

期望提分幅度预测选用一个轻量级的 **XGBoost 回归树模型**，输入特征包括：当前 5 维 Rubric 分数、历史标注员一致性分值、Prompt 长度、语义 Embedding。由于特征维数低，XGBoost 推理耗时小于 $2\text{ms}$，完全不拖慢大盘速度。

### 13. 上下游资产依赖条件

依赖方案 10 提供的连续型标量分数作为其效用提升幅度的度量尺，并依赖方案 12 输出的宏观缺陷权重。

### 14. 潜在工程风险与规避策略

- **风险：** 成本估算模型失效。如果专家人力的真实单价因为排班变动发生剧烈抖动，而系统内的 $C(a)$ 参数没有同步更新，会导致算账结果全面失真。
- **规避策略：** 与财务排班系统的 ERP 接口打通，每周一凌晨自动拉取最新的“标注员单字单价”与“专家时薪”，动态热更新效用公式中的成本分母。

## 14. 微观流程收益路由器（基于 Bandit 与规则的动态调度中枢）

- **团队决策：保留（全平台最硬核的“中枢大脑”，决策执行者 🌟）**

### 1. 方案详细介绍

微观流程收益路由器是整个白皮书架构的**终极执行者**。它承接方案 13 计算出的动作效用矩阵，利用**上下文多臂老虎机（Contextual Multi-Armed Bandit）算法**，结合线上实时的人力带宽、预算余额以及当前样本的特征，在“直接放行、原人保姆级返工、一审组长复核、二审专家仲裁、Prompt 拆分重标”这 5 个相互竞争的流水线分枝（Arms）之间，为每一条数据做出最优的动态路由选择。它不仅能严格执行确定性规则，更能在未知空间里自主探索最高 ROI 的调度路径。

### 2. 链路位置合规性

处于**评测打分与算账完毕后、数据分流流向下一执行终端的核心交汇点**。

### 3. 核心作用与目的

**彻底废除传统的固定流水线。** 让数据流实现自适应的智能化分流，解决众包长尾环境下由于“死板流程”导致的资源浪费或高难样本反复流转无人能解的系统性溃疡。

### 4. 方法论有效性根源

文生图数据的难易度呈现高度的长尾分布。固定的流水线（如一审 $\rightarrow$ 二审 $\rightarrow$ 终审）是对均值数据的妥协，必然导致简单数据过度质检（浪费钱）、极难数据反复卡死（浪费时间）。基于 Bandit 算法的路由器将每条样本视为一个独特的上下文环境（Context），在“利用历史最优经验（Exploit）”与“探索未知高效路径（Explore）”之间实现数学上的完美动态平衡（LinUCB / Thompson Sampling 机制）。

### 5. 链路输入与输出

- **输入（Inputs）：** 方案 13 输出的单条样本动作效用矩阵 $U(s, a)$、当前大盘的剩余总预算令牌（Tokens）。
- **输出（Outputs）：** 唯一的路由分流决定（例如：`Route to Arm_03: Expert Arbitration`）。

### 6. 链路综合提升

实现全平台生产效能的自适应最大化。在预算充足时自动提高探索度以追求极致模型上限，在预算吃紧时自动切换为极限防御姿态（收榨流），确保在任何外部财务周期下，交付物都能维持在帕累托最优边界（Pareto Frontier）上。

### 7. 强化学习（RL）涉及度

- **涉及状态：** **深度涉及在线强化学习（Bandit 属于单状态在线 RL）**。
- **【小白/PM 降维释义层 —— 角色扮演】：**
  > - **Policy（策略 / 本方案扮演的“赌场最精明的王牌大堂经理”）：** 这家赌场里有 5 个老虎机（摇臂），分别叫【直接通过、原人返工、组长看一眼、高级专家精修、拆碎重来】。每往里面塞一条数据，老虎机就会吐出不同的收益（模型提分）。
  > - **State / Context（状态上下文 / 塞进来的数据长啥样）：** 眼前塞进来一封高难度的硬骨头数据：“长着九只机械翅膀的赛博朋克大天使”。
  > - **Action（动作 / 经理决定摇哪台机器）：** 经理（Bandit）看了一眼这大天使（Context），根据历史记忆，如果摇【原人返工】，原人大概率看不懂机械结构，机器会吐出零收益；如果摇【高级专家】，虽然能修好，但是要扣掉 5 块钱巨额筹码。这时候，经理决定尝试一个新套路——摇一下【拆碎重来】摇臂，把翅膀和天使拆成两个任务分别下发。
  > - **Reward（奖励 / 后台反馈的真金白银收益）：** 拆分后的任务下发下去，标注员非常轻松地完成了高质量交付，送回评测中枢经典 RM 一测，分数暴涨 0.6 分，且只花了 1 块钱！经理在后台欢呼一声，把这次成功经验死死记在小本本上。下一次再遇到类似复杂的机械多主体样本时，它就会更倾向于走这个“拆分路由”的隐藏高收益路径。

### 8. 效能衡量与量化方法（对比测试法）

- **核心评估指标：** **大盘综合累计奖励值（Cumulative Reward / Total Model ROI）**、路由收敛耗时、死单滞留率。
- **量化对比实验设计：** 全盘开启 2 万条生图任务，进行 1:1 的微观分流对抗赛。
- 规则路由组（1万条）：采用死板的硬性 Hard Code 规则（如低于 60 分一律原人改，改两次不行送专家）。
- Bandit 智能路由组（1万条）：由本方案的 Contextual Bandit 算法在线自适应调配分流。
- 最终统计：在消耗同等总预算的情况下，对比两组洗出的终验数据让模型吞噬后的综合提分幅度，并绘制“累计收益收敛曲线图”。智能路由组由于消除了“死板流程造成的无效空转”，其累计增量收益预计能实现 **$35\%$ 以上的跨越式领先**。

### 9. 落地业务具体示例

- **具体业务场景：** 模型生成了一张带有精细英文字母的海报图，由于“英文单词拼写错误”，方案 09 裁判打出了 40 分的极低分。
- **传统路径的悲剧：** 传统系统会自动退回给原标注员。原标注员可能英文水平有限，面对 “A modern poster for a coffee shop with the text 'CHILL OUT'” 这种意图，折腾了 3 遍还是把 “CHILL” 拼错了，导致该样本在流水线中无限死循环，严重拖慢交付周期。
- **Bandit 路由器的神仙操作：** 路由器捕捉到了这个环境上下文（含有 `Text Rendering` 缺陷，且历史记录显示原标注员在英文维度上的能力评级较低）。
- **动态决策动作：** 老虎机算法果断放弃【原人返工】摇臂，直接触发【专家仲裁（由通过英语六级的专项高级质检员直接介入接管）】或者【触发方案 01 提示词逆向清洗】。仅仅花费 1 次路由，该样本便在高级质检员手中一锤定音，耗时 2 分钟完成高质修复，直接放行，成功解救了前线陷入泥潭的普通标注员。

### 10. 落地优先级评分及理由

### 12. 核心算法与模型选型提示

推荐选用 **LinUCB 算法（Linear Contextual Bandit）**。在工业级高并发场景下，LinUCB 的收益估算具有闭式解（Closed-form Solution），计算极其简单且对显存无要求，单次路由选择仅需进行一次矩阵乘法，可以轻松应对高并发的标注提交洪峰。

- **规避策略：** 引入“安全刚性规则护栏（Safety Guardrails）”。在 Bandit 算法外面包裹一层确定性的逻辑兜底：例如规定“只要敏感词质检未通过，一律一票否决弹窗退回，Bandit 算法无权剥夺此规则”。同时设定单日最大专家预算熔断阈值，一旦探索触发资金红线，系统立刻自动降级为传统保守路由模式。

## 15. 元指标进化器（基于得分熵值监控的 Meta-Rubric 自我升级）

- **团队决策：保留（保障评测体系永远先进的“防腐剂”）**

### 1. 方案详细介绍

评测标准不是一成不变的法条。本方案是一个专门用来“监督、评测、升级裁判标准本身”的 Meta-Agent（元指标进化器）。它在后台持续监控大盘各项 Rubric 维度的得分分布，利用信息熵（Information Entropy）数学模型评估现有指标的“区分度”与“先进性”。一旦发现某项原本极难的指标随着下游模型的演进、其及格率趋近于 100%（即该指标已彻底失去对优劣数据的筛选能力），本方案将自动拉响预警，并调用顶级大模型重新拆细、升级或淘汰该项 Rubric 条款。

### 2. 链路位置合规性

处于**指标库与规则配置中心的最顶层管理流**。它是整个平台生态位上的“立法者”。

### 3. 核心作用与目的

**防止评测体系“通货膨胀”与标准老化。** 确保随着公司自研 T2I 模型能力的不断变强，我们的标注与评测门槛也同步自动抬高，始终保持对大模型隐空间的极限高压压测姿态。

### 4. 方法论有效性根源

基于信息论中的**最大熵原理（Maximum Entropy Principle）**。一个完美的考卷，其分数的分布应当呈现合理的方差，每一道题目都应该具备最高的“信息增益”。如果一门考试所有人都考了100分（得分熵值趋近于0），说明这门考试的题目已经退化成了毫无价值的废话。通过监控得分熵，能够以绝对理性的数学视角发现标准陈旧的客观事实。

### 5. 链路输入与输出

- **输入（Inputs）：** 大盘运行 1 个月累积的数百万条分维 Rubric 得分分布历史统计序列。
- **输出（Outputs）：** 《Rubric 区分度枯竭预警报告》、调用大模型自动生成的《Meta-Rubric v3.0 升级草案》。

### 6. 链路综合提升

实现评测指标的“无痛无感自我迭代”。以往一条标注标准的修改，需要算法、产品、数据三个团队开两周的跨部门会议反复拍板，而本方案将规则的修正周期拉入“天级”的自愈轨道。

### 7. 强化学习（RL）涉及度

**涉及状态：** **属于元学习（Meta-Learning）与环境自适应（Environment Adaptation）范畴，不直接调用传统在线 RL 推理算法。**
**技术平替阐述：** 本方案处于强化学习生态位的最顶层——**动态重塑奖励函数（Reward Function）的定义空间**。它通过监控大盘得分的信息熵并调用旗舰级大模型重写 Rubric 标准，本质上是在动态改变下游强化学习（DPO/PPO 训练）任务中的“游戏规则”。虽然其自身不依赖策略梯度（Policy Gradient）或反向传播更新，但它通过对环境奖励信号的自适应收紧，能有效防止下游强化学习模型在训练时发生“奖励作弊（Reward Hacking）”与“策略退化”风险。

### 8. 效能衡量与量化方法（对比测试法）

- **核心评估指标：** 指标空间总体信息熵（Total Information Entropy）、标准升级带来的模型硬核难例过滤召回率。
- **量化对比实验设计：** \* **信息熵量化公式**：对于某项 Rubric 维度 $X$，其得分划分为 $n$ 个区间，统计每个区间的概率 $P(x_i)$，计算其香农熵：

$$H(X) = -\sum_{i=1}^{n} P(x_i) \log_2 P(x_i)$$

当监测到 $H(X) < 0.35$ 且均值 $\mu > 95$ 时，触发红色进化预警。

- 对比测试：将进化前后的两套 Rubric 指标同时用于最新的旗舰版 T2I 模型评测，统计两套指标对轻微穿模画面的辨识度。新版 Rubric 的缺陷识别率通常能实现数倍的反超。

### 9. 落地业务具体示例

- **系统监控发现：** 连续两周，大盘在 `Aesthetic Quality -> Exposure Consistency`（美学质量 -> 曝光一致性）这一 Rubric 维度上的得分呈现恐怖的单峰分布：99.2% 的图片都拿了满分。
- **原因归因：** 自研模型的底座已经升级，天然具备了完美控制曝光的能力，这道题目对于现在的模型而言已经太简单了。
- **进化动作：** 元指标进化器启动。它下令淘汰过时的曝光指标，并调用旗舰大模型反思重写指标库，自动将其分裂并升级为更硬核、更有区分度的两个全新二级子指标：`[微观高光动态范围对齐度]` 和 `[多光源阴影逻辑一致性]`，直接挂载到前线评测流，瞬间让大盘得分重新回归到健康的 75 分正态分布空间。

### 14. 潜在工程风险与规避策略

- **风险：** **标准剧烈抖动导致历史数据资产贬值（Version Incompatibility）**。如果系统今天升级这个指标，明天修改那个标准，会导致上个月标的高分数据拿到这个月变成了不及格垃圾，直接导致历史多模态模型真值数据集（Ground Truth Dataset）的版本发生严重断层与混乱。
- **规避策略：** 指标进化器**必须遵循“双版本并行（Shadow Testing）与映射兼容”原则**。新标准上线后，旧标准必须在后台静默运行 1 周，并由系统自动拟合出一个“新旧分数转换数学矩阵”，确保历史资产的分数能够通过公式平滑映射到新标准的坐标系中，死守数据资产的跨版本稳定性。
