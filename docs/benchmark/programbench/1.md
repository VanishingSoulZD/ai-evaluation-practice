ProgramBench官方定位是：

> 给AI Agent一个编译后的程序(binary)和文档，让它从零设计架构、选择语言、实现完整代码，并通过行为测试复现原程序。([ProgramBench][1])

它不是传统“修bug”，而是在测：

> AI Agent是否具备接近软件工程师的“从需求 → 架构 → 实现 → 验证”的端到端软件构建能力。

# Slide 8：评分机制（重点）

必须讲清楚。

ProgramBench两个指标：

## 1. Resolved

定义：

> 所有hidden behavioral tests全部通过

例如：

task:

1000 tests

结果：

1000/1000

= Resolved

---

## 2. Almost

定义：

> 通过 ≥95%的测试

例如：

1000 tests

通过：

960

= Almost

([ProgramBench][3])

---

为什么两个指标？

因为：

真实软件：

几乎正确 ≠ 完全正确

但是：

商业软件：

1%的错误也可能不可接受。

# Slide 10：为什么分数这么低？（核心解释）

不要让大家误解：

“AI很菜”。

解释：

ProgramBench刻意去掉：

### 1. 代码上下文

SWE-bench：

```
已有百万行代码
```

ProgramBench：

```
0行源码
```

---

### 2. 人类架构经验

AI必须自己决定：

- 模块设计
- 数据结构
- API设计

---

### 3. 长周期一致性

大型项目：

几十万LOC

需要：

- planning
- memory
- verification

所以：

低分不是失败。

而是证明：

> 当前Agent距离自主软件工程还有巨大距离。
