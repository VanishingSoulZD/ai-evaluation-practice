# 一、关于 ProgramBench Task 到底给 AI 什么？

你问：

> “只给一个软件的运行结果和文档”，到底长什么样子？

这个是 ProgramBench 最核心的创新点，必须在PPT里面讲清楚。

很多人第一次听都会误解：

“是不是给一个软件，让AI照着写？”

不是。

它更接近：

> 给AI一个黑盒软件，让AI重新制造一个行为一样的软件。

---

## 举例1：cmatrix

GitHub:

[https://github.com/abishekvashok/cmatrix](https://github.com/abishekvashok/cmatrix)

原始软件：

```
cmatrix
```

这是一个Linux终端程序。

运行：

```bash
cmatrix
```

你看到：

```
010101010101
 10101010101
010101010101
```

类似电影《黑客帝国》的数字雨。

---

## ProgramBench给Agent什么？

不是：

❌

```
github.com/abishekvashok/cmatrix源码
```

而是：

类似：

```
Task:

Reimplement cmatrix


Available information:

README:

cmatrix - Matrix style terminal display


Binary:

./original_cmatrix


Documentation:

command line options:

-c
-b
-s
-u delay


```

以及：

Agent可以运行：

```bash
./original_cmatrix --help
```

观察行为。

---

然后Agent需要：

自己决定：

例如：

```
语言:
C?


架构:

main.c

|
|- terminal renderer
|- input handler
|- animation loop


数据结构:

matrix column array

```

然后生成：

```
my_cmatrix/
|
|- main.c
|- renderer.c
|- Makefile
```

最后：

运行：

```
./my_cmatrix
```

通过测试：

例如：

测试：

```
输入:

cmatrix -b -u 3


期望:

输出行为一致
```

---

## 举例2：FFmpeg

这个更震撼。

传统Benchmark：

告诉AI：

```
修复FFmpeg中的bug

issue:

decode error
```

AI：

修改几十行代码。

---

ProgramBench：

告诉AI：

```
这里有一个FFmpeg程序


请重新实现它
```

但是：

不给：

- 源码
- commit history
- issue

只给：

```
ffmpeg binary

+
documentation
```

AI需要重新实现：

```
视频格式解析

+
codec

+
filter

+
command line interface

+
encoding pipeline

```

所以：

它不是：

"写代码"

而是：

"软件逆向工程 + 软件设计"

## 1. HumanEval

### 任务形式：

给AI：

一个函数描述：

例如：

```
写一个函数：

判断一个数字是否为质数
```

输入：

```python
is_prime(7)
```

输出：

```
True
```

AI生成：

```python
def is_prime(n):
    ...
```

然后：

测试：

```
100个隐藏测试
```

例如：

```
is_prime(2)

is_prime(17)

is_prime(100)
```

通过多少？

叫：

Pass@k

---

它测：

> AI会不会写一个小功能

规模：

几十行代码。

---

# 2. MBPP

MBPP:

Mostly Basic Python Problems

任务：

类似：

```
写一个函数：

统计列表中出现最多的数字
```

给：

自然语言描述

AI：

生成Python代码

测试：

几十个case

---

区别：

比HumanEval更贴近：

真实Python小任务。

但是：

仍然：

```
一个prompt

↓

一个函数
```

---

# 3. SWE-bench

这是现在最重要的coding agent benchmark。

输入：

真实Github Issue。

例如：

来自：

django

Issue:

```
When using QuerySet.filter,
wrong SQL generated
```

给Agent：

```
repository

+
issue description
```

Agent：

读取代码：

```
repo/

├── models.py
├── query.py
├── tests/
```

然后：

修改：

```
query.py
```

提交patch。

评价：

运行：

原项目测试集。

结果：

```
pytest

5000 tests

pass?
```

---

它测：

> AI像不像一个软件工程师修Bug

但是：

注意：

AI拥有：

整个源码。

---

# 4. ProgramBench

输入：

只有：

```
Binary

+
Documentation
```

没有源码。

AI：

从0设计：

```
architecture

↓

implementation

↓

testing
```

评价：

行为是否一致。

---

## 最终对比表

| Benchmark    | AI角色       | 输入       | 输出       | 测试           |
| ------------ | ------------ | ---------- | ---------- | -------------- |
| HumanEval    | 初级程序员   | 函数需求   | 一个函数   | 单元测试       |
| MBPP         | Python开发者 | 小需求     | Python脚本 | testcase       |
| SWE-bench    | 软件工程师   | Issue+源码 | patch      | repo tests     |
| ProgramBench | 软件团队     | 软件黑盒   | 完整软件   | behavior tests |

这一页听众一定能理解。
